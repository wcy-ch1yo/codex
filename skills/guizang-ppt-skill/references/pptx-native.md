# 原生 PowerPoint 转译规范

本文件把 `guizang-ppt-skill` 的网页视觉系统映射到可编辑的 `.pptx`。目标不是“做一个像 PPT 的网页”，而是用 PowerPoint 原生对象复现同一套风格与版式。

## 1. 构建契约

- 统一画布：`1280 × 720`，16:9。
- 用 `@oai/artifact-tool` 的 JavaScript ESM API 构建和导出。
- 先用 `Presentation.create({ slideSize: { width: 1280, height: 720 } })`。
- 用 `PresentationFile.exportPptx` 导出 `.pptx`。
- 禁止整页截图、整页 SVG、整页 canvas 或“HTML 转图片后贴满一页”。
- 每页必须有稳定名称或 `name` 前缀；文字框、色块、线条和图表均保持可编辑。
- 页面可见文本只写观众需要看的内容；设计说明、时间安排和讲稿放进 speaker notes。

推荐入口：

```javascript
import { createDeckKit, colSpan, equalCols } from "./pptx-core.mjs";

const kit = createDeckKit({ style: "swiss", theme: "ikb" });
const s = kit.slide({ background: kit.tokens.paper });

kit.chrome(s, { left: "SWISS / IKB", right: "01 / 18" });
kit.text(s, "title", 64, 92, 900, 100, "先让结论站到台前", {
  fontSize: 54,
  lineSpacing: 1.08,
});
kit.rect(s, "accent-rule", 64, 204, 88, 6, kit.tokens.accent);
kit.notes(s, ["这一页先给出全场结论。", "[Sources] 本文数据来自……"]);

await kit.save("output/deck.pptx");
```

## 2. 画布与网格

基础约束：

| 项目 | 值 |
|---|---:|
| 画布 | 1280 × 720 |
| 左右边距 | 64 |
| 顶部 chrome | 36-54 |
| 标准内容起点 | 92 |
| 主体区 | 92-640 |
| 页脚基线 | 680 |
| 安全底线 | 696 |
| 12 栏内容宽 | 1152 |
| 12 栏间距 | 24 |

12 栏的列宽约为 `74px`。使用 `colSpan(start, span)`，不要手写近似坐标。常用分栏：

- 7:5 → `colSpan(1,7)` + `colSpan(8,5)`
- 6:6 → `colSpan(1,6)` + `colSpan(7,6)`
- 8:4 → `colSpan(1,8)` + `colSpan(9,4)`
- 3 等分 → `equalCols(3)`
- 4 等分 → `equalCols(4)`
- 6 格 → 3 列 × 2 行，使用 `equalCols(3)` 与 `kit.row(2, ...)`。

间距使用 8px 模数：`8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96 / 160`。不要用“看起来差不多”的任意间距。

## 3. 主题令牌

### 风格 B · 瑞士风

每套主题只允许一个 accent。灰阶固定，不要改纸色与灰阶。

| token | IKB | 柠檬黄 | 柠檬绿 | 安全橙 |
|---|---|---|---|---|
| paper | `#FAFAF8` | `#FAFAF8` | `#FAFAF8` | `#FAFAF8` |
| ink | `#0A0A0A` | `#0A0A0A` | `#0A0A0A` | `#0A0A0A` |
| grey1 | `#F0F0EE` | `#F0F0EE` | `#F0F0EE` | `#F0F0EE` |
| grey2 | `#D4D4D2` | `#D4D4D2` | `#D4D4D2` | `#D4D4D2` |
| grey3 | `#737373` | `#737373` | `#737373` | `#737373` |
| accent | `#002FA7` | `#FFD500` | `#C5E803` | `#FF6B35` |
| accentOn | `#FFFFFF` | `#0A0A0A` | `#0A0A0A` | `#FFFFFF` |

IKB 主题在 PPT 中可增加 `accentBright = #5B7BFF` 仅用于深底页的小面积高亮；不要把它当成第二个主题色。

### 风格 A · 电子杂志

主题只改变 ink/paper，不改变排版层级。

| token | 墨水经典 | 靛蓝瓷 | 森林墨 | 牛皮纸 | 沙丘 |
|---|---|---|---|---|---|
| ink | `#0A0A0B` | `#0A1F3D` | `#1A2E1F` | `#2A1E13` | `#1F1A14` |
| paper | `#F1EFEA` | `#F1F3F5` | `#F5F1E8` | `#EEDFC7` | `#F0E6D2` |
| tint | `#E8E5DE` | `#E4E8EC` | `#ECE7DA` | `#E0D0B6` | `#E3D7BF` |
| inkTint | `#18181A` | `#152A4A` | `#253D2C` | `#3A2A1D` | `#2D2620` |

风格 A 不额外引入彩色 accent；强调依靠墨色、纸色、字号和细线完成。只有图片或数据图才允许使用其自身颜色。

### 颜色使用规则

- 一份 deck 只选一套主题。
- 一页最多一个 accent 色；不要一页蓝、一页黄、一页橙。
- 深色底上的反白文字必须是 paper 或 `accentOn`，不要用低对比灰。
- 细线使用 1px；强调线最多 2px。风格 B 不画粗边框。
- 风格 B 禁止渐变、阴影、圆角、玻璃拟态和半透明叠加。

## 4. 字体与层级

可用字体：

| 角色 | 字体 |
|---|---|
| 风格 A 标题 | `Noto Serif SC`（缺失则用 `SimSun`） |
| 中文正文 | `Microsoft YaHei` |
| 数字/英文 | `Arial` |
| 元数据 | `Arial`，必要时用大写与字距模拟 mono |

风格 B 必须全部无衬线，不能使用风格 A 的衬线标题。

建议字号：

| 角色 | px |
|---|---:|
| 封面巨标题 | 80-108 |
| 章节/宣言 | 56-76 |
| 正文页标题 | 40-56 |
| 卡片标题 | 24-32 |
| 正文 | 18-22 |
| caption / meta | 12-16 |
| 巨数 KPI | 72-132 |

处理中文标题时按字数分档：

- 1 行且 ≤ 8 字：可到 80-96px。
- 2 行且每行 ≤ 8 字：64-80px。
- 2 行且存在 9-12 字：52-64px。
- 超过 12 字：先改写标题；不要靠缩小字体硬塞。

同一页内，小字要比大字更粗；正文不要用极细字重。风格 B 的大标题用较轻字重，小标签用较粗字重。

## 5. 组件映射

网页类名只作为视觉意图，不直接进入 PPT。按下列方式转成原生对象：

| HTML/视觉意图 | PPT 对象 |
|---|---|
| `.chrome-min` | 顶部两个文本框 + 1px 细线 |
| `.foot` | 底部两个文本框 + 1px 细线 |
| `.h-hero` / `.h-xl` | 独立大文本框，禁止放进卡片 |
| `.kicker` / `.t-meta` | 小型大写文本 + 短横线 |
| `.card-fill` | 直角浅灰矩形 + 内嵌文本 |
| `.card-accent` | 单一 accent 矩形 + 反白文本 |
| `.hr-hairline` | 1px 横向矩形 |
| `.dot-mat` | 小方块阵列；瑞士风用 6×6 或 8×8 直角块 |
| `.ring-mat` | 描边椭圆；只做装饰，不承载文字 |
| `.bar-tower` | 底对齐的纯色矩形，高度由数据计算 |
| `.bar-fill` | 底对齐/左对齐的细长矩形 |
| `.timeline-h` | 一条 1px 横线 + 等距节点 + 上下交错标签 |
| `.timeline-v` | 一条 1px 竖线 + 等距节点 + 右侧信息列 |
| `.loop-diagram` | 4 个矩形节点 + 4 条直线/折线，不使用圆形文字 |
| `.system-diagram` | 嵌套直角矩形或同心描边框 |
| 图片槽位 | `slide.images.add({ fit: "cover" | "contain" })` |

不要把每个组件都做成独立“卡片”。优先用开放式版面、色块和线条建立关系；只有版式明确要求时才用矩形卡片。

## 6. 页眉、页脚和页码

每页只保留一套 chrome：

- 左上：章节名 / 主题名，14px，短横线前缀。
- 右上：`当前页 / 总页数`，14px，右对齐。
- 底部：来源、系列名或一句极短说明，14px；页码在右下。
- 不使用可点击翻页按钮、圆形分页点、网页式导航条。

封面和收尾页可以减少 chrome；正文页保持一致。

## 7. 演讲备注

每页 `speakerNotes` 按以下顺序：

```text
这一页的任务：……
要讲清的解释/例子：……
与下一页的连接：……
[Sources] 机构/作者，标题，年份，URL
```

备注 2-5 条即可。不要把整页文字复述一遍，也不要在页面上显示“讲述要点”。

## 8. 图片与素材

- 照片、产品图、人物图、截图和复杂信息图进入指定槽位。
- 单张主视觉优先放在 S22 上半部，比例约 21:9。
- 2-3 张同组图片放在 S15/S16 的统一格子中，统一裁切和高度。
- UI/代码/文字密集截图用 `contain`，不要为了铺满裁掉关键内容。
- 图片内不要嵌入标题、页码、logo、页脚或边框。
- 生成图片时，提示词必须写清比例、主体安全区和“不要文字/页脚/边框”。中文信息图必须使用中文。

## 9. 风格 B · 22 个登记版式

以下 `S01-S22` 与 `references/swiss-layout-lock.md` 一一对应。版式 ID 是内部计划字段，不必显示在页面上；可在对象 `name` 前缀中保留。

### S01 · Index Cover

- 三行结构：顶部 chrome、中部左编号/右大标题、底部短副标与元信息。
- 左侧大编号只做视觉锚点，宽度约 180-240；右侧标题按 7 栏宽度排版。
- 背景可用 full IKB、paper 或 ink 半屏；一份 deck 只选一个封面变体。
- 主标题只能用 1-2 行；不要加四个以上信息块。

### S02 · Vertical Timeline + KPI

- 顶部左对齐标题；中部为纵向时间线 `4` 个节点；底部为 4 个 KPI。
- 时间线轴固定在 x=112 附近，节点间距约 90-110；右侧列依次是年份、巨数、短标签、描述。
- 每个节点必须有真实时间/量化数据；没有数据时改用 S11。
- 底部 KPI 四等分，数字、单位、注释垂直排列，不能压到页脚。

### S03 · Split Statement

- 左右各半屏，中间 `1px` 竖线。
- 左半部分放 1-2 行大字结论或 IKB 色块；右半部分放解释、三条支撑或引文。
- 标题可跨到左半部分；不要把小标题单独塞到左栏。
- 视觉上是“一个判断 + 一段理由”，不是两张对称卡片。

### S04 · Six Cells

- 顶部标题，下面 3 列 × 2 行六格。
- 每格固定四件套：序号、短标题、一行解释、可选线性图标。
- 单元用细线分隔，不要做六张带阴影的圆角卡。
- 六项必须等权；少于 5 项换 S05/S19，超过 6 项换 S16。

### S05 · Three Layers

- 顶部标题 + 右侧说明，下面三条横向堆叠层块。
- 每层左侧为编号/层级名，右侧为一句作用和一行关键属性。
- 高度可以按信息量略不等，但层与层必须对齐同一左右边界。
- 适合三层架构、三层筛选、三级流程，不用于自由罗列。

### S06 · KPI Tower

- 左侧标题 + 解释，右侧四根不等高柱，底部标签。
- 柱体 `accent` 纯色，从统一基线向上生长；数字放在柱体上方或柱顶附近。
- 高度必须由真实数据决定；没有可比数据时不能使用本版式。
- 柱宽约 120-150，柱间距约 32；不要让柱体碰到页脚。

### S07 · H-Bar Chart

- 顶部标题，下面 5-10 行横向条形。
- 每行三列：标签（约 220px）、条形轨道（剩余宽度）、数字（约 80px）。
- 条形只使用单一 accent；轨道可以为 `grey1` 或细线。数字右对齐。
- 没有真实百分比、评分或统一量纲时，不能伪造条形数据。

### S08 · Duo Compare

- 左右两列 6:6，中间 1px 竖线。
- 每列顺序：小标签、较大标题、解释段落、可选三到四条要点。
- 左侧与右侧行距、字号、标题高度必须镜像一致。
- 可把右侧换成地图/关系图，但仍保留 S08 的双栏骨架和标题轴。

### S09 · Dot Matrix Statement

- 页面只放一个大声明，通常 2-3 行，配点阵或描边圆环。
- 主标题占页面中段 50-60%；右上或左下保留大块负空间。
- 点阵只做低对比装饰，不能遮字或越出画布。
- 适合章节转场、观点强化；不适合承载多条解释。

### S10 · Split Closing

- 左半屏放大字收束宣言，右半屏放 3 条 takeaway。
- 左半屏可用 IKB/ink，右半屏用 paper；两条不对称但同高。
- 每条 takeaway：编号、短标题、一句解释；第三条可加 accent。
- 底部写来源、组名或结束语，不要写“谢谢观看”作为唯一内容。

### S11 · Horizontal Timeline

- 顶部标题，下面一条横轴和 4-7 个等距节点。
- 节点是 8×8 直角方块；年份/编号在上，名称在下，必要时上下交错。
- 节点必须共用一条轴；不要做成漂浮的独立卡片。
- 流程超过 7 步时合并阶段或拆分页面，不要压小文字。

### S12 · Manifesto + Ink Banner

- 上部 70% 为 2-3 行大字宣言或关键结论，下部 18-22% 为通栏 ink/IKB 条。
- 通栏条内放一组极短结论或页码/章节信息，不要塞长段落。
- 上部正文与大字结论之间要有明显层级差。
- 用于阶段结论、方法论落点或章节收束。

### S13 · Three Forces

- 左 4-5 栏放 ink 大色块或一句主判断；右侧 3 张等高卡。
- 卡片使用同一底色和同一层级，不要三张不同颜色。
- 每张卡：编号/字母、标题、两行解释。
- 适合三个驱动力、三个限制、三个变量；不适合六项清单。

### S14 · Loop Form

- 左侧 4 步编号列表，右侧一个闭环示意。
- 闭环由 4 个直角节点和 4 条直线/折线组成；文字标签放在节点外侧。
- 箭头/线条先画，节点后画，避免线穿过节点和文字。
- 必须真有循环关系才使用；线性流程应改用 S11。

### S15 · Matrix + Hero Stat

- 顶部标题；中部 6×2 矩阵；底部放大号总指标。
- 矩阵单元统一尺寸、间距和编号；可用小图替换部分单元，但图片比例必须一致。
- 大指标是页面视觉落点，数字与单位同框，注释放在数字下方。
- 没有矩阵关系或一个总结数据时，不要用此页。

### S16 · Multi-card Brief

- 顶部标题，下方 3×2 六张微卡。
- 每张卡：编号/图标、短标题、一行说明；可加入统一比例的小图。
- 卡片以轻量信息速览为主，不能堆成长段落。
- 多图必须使用同一裁切比例和同一卡片高度。

### S17 · System Diagram

- 顶部左侧小章节标签 + 右侧一句总述，中部是三层系统图，底部三列解释。
- 系统图用嵌套矩形或同心描边框，层与层之间有清晰包含关系。
- 连线先画，容器后画；文字不放进 SVG/线条里。
- 适用于层级、生态、平台结构，不适合普通三点列表。

### S18 · Why Now

- 顶部标题和一句背景，中部三列递进论点，底部放大号证据或结论。
- 三列结构相同：编号、短标题、两到三行解释。
- 底部巨数必须有真实量纲；没有数据就删除巨数，不要造数字。
- 适合“为什么是现在 / 为什么必须做 / 三层理由”。

### S19 · Four Cards

- 顶部一条 accent 短线 + 标题；下方四列等宽卡片。
- 四列顺序一致：编号、标题、解释；卡片底色相同。
- 条件允许时只把其中一列改成 accent 底以突出重点，但不要多色。
- 适合四项原则、四步方法、四个结论。

### S20 · Stacked KPI Ledger

- 纵向 4 行账单：左侧标签、右侧大数、底部细线。
- 每行数字同为右对齐；数字字号逐级可变化，但基线一致。
- 行与行之间留出明显空白；不要把所有内容做成表格。
- 必须有多项真实 KPI，且用户需要横向阅读比较。

### S21 · Tech Spec Sheet

- 左侧标题列、右侧三 KPI 与右下竖线矩阵，底部一个总结数字。
- 三 KPI 顶部用 hairline，数字/单位/标签按固定顺序。
- 右下竖线矩阵底对齐，9-12 根柱不能越右边距。
- 信息密度高，适合规格和 benchmark；不适合讲故事。

### S22 · Image Hero

- 上半部约 55-60% 放 21:9 或接近 21:9 主图，左上叠一个 paper 标题块。
- 下半部放 1-2 行解释和三列 KPI；三列顶线与数字对齐。
- 主图主体必须在中央安全区，标题块不能盖住人脸/产品或关键证据。
- 没有真实图片时禁止使用；不要用灰色占位图冒充最终视觉。

## 10. 风格 A · 10 个登记版式

### L01 · 开场封面

- 顶部 chrome + 中部大标题 + 副标 + lead 段落 + meta；整体垂直居中。
- 标题用衬线，正文用非衬线，元数据用小号非衬线/等宽感文本。
- 背景使用主题 paper 或 deep ink；不要加 WebGL 流体图，改用大面积平色和一条极细规则线。
- 标题最多 2 行；如果标题超过 16 个汉字，先压缩文案。

### L02 · 章节幕封

- 章节 kicker、超大标题、一句引语；内容居中偏左。
- 与封面交替使用 ink/paper 背景，承担段落间的“呼吸”。
- 不需要数据、卡片或图标；页脚可只保留章节名。

### L03 · 数据大字报

- 标题 + lead + 3×2 或 4×2 数据卡。
- 每卡：小标签、巨数、注释；只保留必要的单位。
- 数字使用 Arial，字重比正文更细；卡片之间用空白和细线，不用阴影。

### L04 · 左文右图

- 左 7 栏：kicker、标题、lead、短段落；右 5 栏：16:10 或 4:3 图片。
- 图片顶部与标题顶部对齐；caption 在图片下方，不压进图片。
- 图片当作叙事证据，不要放第二套标题或横幅。

### L05 · 图片网格

- 顶部标题 + 2-3 列图片网格，统一高度（约 180-210px）。
- 所有图片使用同一裁切比例；caption 固定在格子下方。
- 每张图必须有信息角色，不能只是装饰。

### L06 · 两列流水线

- 标题下放两条横向流程，每条 3-5 步。
- 每步：编号、短标题、一行说明；用 1px 线和节点连接。
- 两条流水线上下排列，保持相同节点宽度和间距。

### L07 · 悬念 / 问题页

- 中心或左上放大问题，配一句引子或“为什么”。
- 版面留白要大，最多再加 2 条线索。
- 用来打断节奏，不要变成信息密集页。

### L08 · 大引用页

- 引用正文用衬线大字，下面跟来源/日期和一行解释。
- 引号或细线只能做辅助，不能抢夺正文视觉重量。
- 一页只放一个引用，不要并列两句互相对抗的话。

### L09 · 并列对比

- 左右 1:1 两栏，每栏一个标签、标题、三到四条要点。
- 左侧可降低明度表示“旧/Before”；右侧保持正常显示“新/After”。
- 两栏用竖线或中间留白分隔，不使用两张彩色卡片。

### L10 · 图文混排

- 左侧 8 栏放标题、lead、正文和 callout；右侧 4 栏放 3:4 或 1:1 辅助图。
- 正文信息量较大时，优先删减段落而不是把字号降到 16px 以下。
- callout 使用左侧 3px 细线和轻微 tint 底，不使用圆角气泡。

## 11. 项目目录与构建流程

推荐把构建文件放在临时目录，最终只把 `.pptx` 放到用户指定位置：

```text
build/
├── build-deck.mjs       ← 项目专用页面函数
├── deck-plan.txt        ← 页码、版式、主题节奏和备注
├── images/              ← 用户素材或生成图
└── out/                 ← PNG 预览和最终 PPTX
```

流程：

1. 复制 `scripts/pptx-core.mjs` 到 `build/`，或在 `build/` 中通过路径导入；确保从该目录运行时能解析 `@oai/artifact-tool`。
2. 写 `deck-plan.txt`，先确认叙事和版式。
3. 写 `build-deck.mjs`，逐页调用 core helper。
4. 先构建一版，导出 PNG 逐页看；不要直接进入“修文案”循环。
5. 运行 `audit-pptx.mjs`；再看 contact sheet 检查节奏。
6. 最终导出到指定路径，并用 PowerPoint/WPS 打开一次确认可编辑。

## 12. 质量检查硬项

- 标题是否无意换行、断字或被色块压住？
- 正文、caption、页码是否低于 14px？
- 两个文本框是否重叠？文字是否超出画布或内容框？
- 三列/四列卡片的基线是否一致？
- 是否出现两个不同 accent 色？
- 是否有圆角、阴影、渐变或网页浮层？
- 图片主体是否被裁掉？三张图的裁切比例是否一致？
- 页脚是否被正文或最后一行数据压住？
- 备注是否包含来源？可见页面是否出现 `[Sources]` 或讲解稿？
- 每页的 layout ID 是否真的匹配内容，而不是连续三页同一种卡片？
